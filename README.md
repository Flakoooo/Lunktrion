<div align="center">
  <h1>Система умного дома Lunktrion</h1>
  <p>
    Система для взаимодействия с устройствами внутри локальной сети. Проект состоит из серверной части на ASP.NET Core и клиентского приложения на Avalonia UI.<br><br>
    Цель проекта заключается в объединении устройств в единую систему, позволяющую получать информацию о них и удалённо выполнять команды с сохранением результатов и команд при временном отсутствии устройств в сети.
  </p>
</div>

<div>
  <h2 align="center">Архитектура</h2>
  <p>Система состоит из нескольких основных компонентов:</p>
  <p><b>ASP.NET Core</b> - серверная часть, API, бизнес-логика и взаимодействие с устройствами.</p>
  <p><b>Avalonia UI</b> - клиентское приложение для управления системой и отображения информации.</p>
  <p><b>PostgreSQL</b> - основное хранилище данных.</p>
  <p><b>Redis</b> - кэширование данных.</p>
  <p><b>RabbitMQ</b> - хранение данных, требующие каких-либо действий.</p>
  <p><b>SignalR</b> — обмен данными между сервером и подключёнными устройствами в реальном времени.</p>
  <p><b>Docker Compose</b> — запуск компонентов системы и инфраструктуры.</p>
</div>
<div>
  <h2 align="center">Возможности</h2>
  <h3>Информация об устройствах</h3>
  <p>Система позволяет получать информацию сразу о нескольких устройствах, подключённых к системе.</p>
  <ul>
    <li>название</li>
    <li>производитель</li>
    <li>операционная система</li>
    <li>информация о процессорах (название, количество ядер и потоков)</li>
    <li>информация о видеокартах (название, объем памяти в МБ)</li>
    <li>информация об оперативной памяти (производитель, объём в ГБ, тип, частота в MHz)</li>
    <li>информация о физических накопителях (производитель, объем в ГБ)</li>
  </ul>
  <p>
    Информация о комплектующих выводится для каждого отдельного компонента устройства. Например, если устройство имеет несколько модулей оперативной памяти, информация отображается отдельно по каждому модулю.
  </p>
  <h3>Работа в реальном времени</h3>
  <p>
    Основное взаимодействие между сервером и подключёнными устройствами выполняется через SignalR. 
    Это позволяет серверу и нескольким устройствам обмениваться информацией в реальном времени.
    HTTP используется для получения данных, которые уже доступны на сервере и не требуют непосредственного обращения к конкретному устройству.
    В дальнейшем планируется добавить дополнительные способы взаимодействия, включая WebSocket, для устройств, для которых использование SignalR может быть нецелесообразным.
  </p>
  <h3>Удалённое выполнение команд</h3>
  <p>Система позволяет отправлять команды на удалённые устройства. Общий сценарий:</p>
  <ol>
    <li>Пользователь вводит команду в клиентском приложении.</li>
    <li>Клиент отправляет команду на сервер.</li>
    <li>Сервер проверяет и обрабатывает команду.</li>
    <li>Команда передаётся целевому устройству.</li>
    <li>Устройство выполняет команду.</li>
    <li>Результат выполнения возвращается на сервер и затем клиенту.</li>
  </ol>
  <p>
    Система учитывает ситуацию, когда устройства временно недоступны.<br>
    Если <b>устройство-инициатор</b> команды отключилось до получения результата, сервер сохраняет результат в Redis на ограниченное время. После повторного подключения устройства результат может быть получен из кэша.<br>
    Если <b>целевое устройство</b> недоступно в момент отправки команды, команда помещается в RabbitMQ. После подключения целевого устройства сервер получает ожидающую команду и передаёт её для выполнения.
  </p>
  <h3>Основа для расширения функциональности</h3>
  <p>Механизм удалённого выполнения команд используется как основа для дальнейшего развития системы. На его базе планируется реализовать:</p>
  <ul>
    <li>удалённое выключение устройств</li>
    <li>просмотр файловой системы</li>
    <li>управление файлами</li>
    <li>получение дополнительной информации об устройствах</li>
    <li>другие операции с удалёнными устройствами</li>
  </ul>

  <h2 align="center">Клиентское приложение</h2>
  <p>
    Клиент разработан на <b>Avalonia UI</b> с использованием архитектурного подхода <b>MVVM</b>. 
    Avalonia используется для построения интерфейса и взаимодействия пользователя с системой, а основная бизнес-логика и работа с устройствами выполняются через backend.

<div>
  <h2 clign="center">Планируемые возможности</h2>
  <h3>Управление файловой системой</h3>
  <p>
    Планируется реализовать управление файловой системой через интерфейс клиента.
    Это позволит отказаться от потенциально опасного выполнения файловых операций напрямую через команды. Сервер будет самостоятельно формировать необходимые команды после проверки операции.
  </p>

  <h3>Потоковая передача изображения</h3>
  <p>Передача изображения с устройства в режиме реального времени для реализации демонстрации экрана.</p>
